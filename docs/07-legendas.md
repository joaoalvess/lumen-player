# 07 — Legendas

Escopo: `Sources/KSPlayer/Subtitle/` (KSSubtitle.swift, KSParseProtocol.swift, SubtitleDataSouce.swift, AudioRecognize.swift) + `Sources/KSPlayer/MEPlayer/SubtitleDecode.swift`. Cobre parsing de texto (SRT/VTT/ASS), decodificação de legendas embutidas via FFmpeg (texto e bitmap: VobSub/DVB/PGS), fontes de legenda online (Shooter/Assrt/OpenSubtitles), reconhecimento de áudio (protocolo) e o modelo de exibição/estilo.

## Responsabilidade

O subsistema resolve três problemas independentes e os unifica sob uma única abstração de consulta por tempo (`KSSubtitleProtocol.search(for:)`, `Sources/KSPlayer/Subtitle/KSSubtitle.swift:125-127`):

1. **Legendas externas (arquivo/URL)**: descoberta (diretório local, cache, APIs online), download lazy e parsing de SRT/VTT/ASS em memória (`KSSubtitle.parts: [SubtitlePart]`).
2. **Legendas embutidas no container**: cada stream de legenda vira um `FFmpegAssetTrack` com fila própria de frames decodificados por `SubtitleDecode` (texto ASS/plain ou bitmap convertido em `UIImage`).
3. **Seleção e exibição**: `SubtitleModel` agrega todas as origens em `subtitleInfos`, mantém a seleção (`selectedSubtitleInfo`), aplica delays e estilo global, e publica `parts` (`@Published`) para a UI (SwiftUI `VideoSubtitleView` ou UIKit `VideoPlayerView`).

O contrato central: dado `currentTime`, a legenda ativa retorna os `SubtitlePart` visíveis naquele instante. Tudo o mais (formato, origem, codec) é detalhe encapsulado atrás de `SubtitleInfo`.

## Fluxo de dados

### A) Registro de origens ao trocar de mídia

1. `KSVideoPlayer.Coordinator.makeView` (SwiftUI) seta `subtitleModel.url` (Sources/KSPlayer/AVPlayer/KSVideoPlayer.swift:142-146); no caminho UIKit é `PlayerView.set(url:)` → `srtControl.url` (Sources/KSPlayer/Core/PlayerView.swift:51,151).
2. `SubtitleModel.url.didSet` (KSSubtitle.swift:297-313): limpa `subtitleInfos`, chama `searchSubtitle(query: nil, languages: [])` (zera resultados de busca anteriores), anexa `SubtitleModel.audioRecognizes` e itera `KSOptions.subtitleDataSouces` (default `[DirectorySubtitleDataSouce()]`) via `addSubtitle(dataSouce:)` (:376-385) — para `FileURLSubtitleDataSouce`, dispara `Task { @MainActor }` com `searchSubtitle(fileURL:)` e anexa `infos` ao terminar. `parts`/`selectedSubtitleInfo` são zerados em `DispatchQueue.main.async` (comentário na :307: não pode mutar `@Published` durante update de UI).
3. Quando o player chega em `.readyToPlay`, o delegate agenda **+1s depois** `addSubtitle(dataSouce: layer.player.subtitleDataSouce)` (legendas embutidas) e, se `options.autoSelectEmbedSubtitle`, seleciona a primeira com `isEnabled` (Sources/KSPlayer/AVPlayer/KSVideoPlayer.swift:224-233; espelhado em Sources/KSPlayer/Video/VideoPlayerView.swift:287-300). O atraso existe porque legendas embutidas no stream de vídeo podem aparecer depois do `readyToPlay` (comentário :226).
4. Busca online sob demanda: `SubtitleModel.searchSubtitle(query:languages:)` (KSSubtitle.swift:360-374) remove os `infos` antigos de cada `SearchSubtitleDataSouce` e refaz a busca em `Task { @MainActor }`. A UI chama isso em `VideoSettingView` (Sources/KSPlayer/SwiftUI/KSVideoPlayerView.swift:696-700).

### B) Seleção e carga

1. UI seta `selectedSubtitleInfo` (menu SwiftUI: Sources/KSPlayer/SwiftUI/KSVideoPlayerViewBuilder.swift:44-56; UIKit: Sources/KSPlayer/Video/VideoPlayerView.swift:518-522; drag-and-drop de arquivo `.srt`: Sources/KSPlayer/SwiftUI/KSVideoPlayerView.swift:306-308).
2. `didSet` (KSSubtitle.swift:315-324): `oldValue.isEnabled = false`, novo `isEnabled = true`; se for `URLSubtitleInfo` remoto e existir um `CacheSubtitleDataSouce` registrado, grava o par (URL da mídia → URL da legenda).
3. `URLSubtitleInfo.isEnabled.didSet` (SubtitleDataSouce.swift:20-28): se `parts.isEmpty`, dispara `Task` não estruturada com `parse(url: downloadURL, userAgent:)` → `URL.data(userAgent:)` (Sources/KSPlayer/Core/Utility.swift:401-412) → `KSSubtitle.parse(data:encoding:)` → `KSOptions.subtitleParses.first { $0.canParse }` → `parse(scanner:)` → `parts` ordenados (merge sort estável, Sources/KSPlayer/Core/Utility.swift:806-838). Erros viram `NSError(errorCode:)` `.subtitleUnEncoding/.subtitleUnParse/.subtitleFormatUnSupport` (Sources/KSPlayer/AVPlayer/PlayerDefines.swift:221-223) — engolidos pelo `try?` do caller.
4. Para track embutida (`FFmpegAssetTrack`), `isEnabled = true` seta `discard = AVDISCARD_DEFAULT` no stream (Sources/KSPlayer/MEPlayer/FFmpegAssetTrack.swift:265-276). Nota: para legendas de **texto** embutidas o setter força `AVDISCARD_DEFAULT` sempre — todos os streams de texto continuam sendo demuxados/decodificados mesmo desselecionados (troca instantânea). `MEPlayerItem.select(track:)` só dispara re-seek para legendas bitmap com `options.isSeekImageSubtitle` (Sources/KSPlayer/MEPlayer/MEPlayerItem.swift:146-153; `KSOptions.isSeekImageSubtitle`, Sources/KSPlayer/AVPlayer/KSOptions.swift:75).

### C) Pipeline embutido (FFmpeg)

1. `MEPlayerItem.createAssetTracks`: para cada stream de legenda cria `SyncPlayerItemTrack<SubtitleFrame>(frameCapacity: 255)` e pendura em `assetTrack.subtitle` (Sources/KSPlayer/MEPlayer/MEPlayerItem.swift:339-343). A fila é `CircularBuffer(sorted: true, expanding: true)` porque "algumas legendas de imagem chegam fora de ordem" (Sources/KSPlayer/MEPlayer/MEPlayerItemTrack.swift:60-64).
2. Thread de leitura: `readLoop` roteia pacotes de legenda para `assetTrack.subtitle?.putPacket(packet:)` (MEPlayerItem.swift:565). `SyncPlayerItemTrack.putPacket` decodifica **sincronamente na thread de demux** (`doDecode`, MEPlayerItemTrack.swift:84-92,113-130); `makeDecode` instancia `SubtitleDecode` para mediaType `.subtitle` (:301-305).
3. `SubtitleDecode.init` (SubtitleDecode.swift:22-33): cria o `AVCodecContext` e alimenta `codecContext.subtitle_header` (cabeçalho ASS gerado pelo FFmpeg com `[V4+ Styles]` e `Format:` de eventos) em `assParse.canParse` — isso pré-carrega `styleMap`/`eventKeys` da instância privada de `AssParse`.
4. `decodeFrame` (SubtitleDecode.swift:37-76): `avcodec_decode_subtitle2`; calcula `start = pts + start_display_time/1000 − assetTrack.startTime` e `duration` de `end_display_time` (ou `packet.duration` como fallback; se 0 → `end = .infinity`). Se o `AVSubtitle` não gerar parts, insere um `SubtitlePart(0,0,nil)` vazio para **limpar** a legenda anterior (comentário :59-60: usar um frame vazio evita o bug de end<start quando a decodificação chega fora de ordem). Cada part vira `SubtitleFrame` e cai na `outputRenderQueue` via completion.
5. `SubtitleDecode.text(subtitle:)` (SubtitleDecode.swift:89-135) trata os 3 tipos de rect:
   - `rect.text` → `NSAttributedString` plano acumulado;
   - `rect.ass` → `assParse.parsePart(scanner:)` (linha sem `Dialogue:`/Start/End → `start=end=0`, sobrescritos pelo timing do pacote; formato exemplificado em KSParseProtocol.swift:82-84);
   - `SUBTITLE_BITMAP` (VobSub `AV_CODEC_ID_DVD_SUBTITLE`, DVB, PGS `AV_CODEC_ID_HDMV_PGS_SUBTITLE`; classificação `isImageSubtitle` em FFmpegAssetTrack.swift:257) → `VideoSwresample(dstFormat: AV_PIX_FMT_ARGB).transfer(format: AV_PIX_FMT_PAL8, ...)` (Sources/KSPlayer/MEPlayer/Resample.swift:146-176) → `CVPixelBuffer.cgImage()` → múltiplos rects combinados por `CGImage.combine` (Sources/KSPlayer/Core/Utility.swift:695-724) → PNG → `UIImage` (comentário :123 justifica PNG: precisa de alpha; HEIC trava a main thread; TIFF fica com fundo verde). `part.origin` guarda a posição do primeiro rect.
6. Consulta: `FFmpegAssetTrack.search(for:)` (EmbedDataSouce.swift:18-22) roda `outputRenderQueue.search { $0.part == time }` — o `CircularBuffer.search` é **destrutivo**: remove os itens casados e avança o `headIndex` (CircularBuffer.swift:117-137).

### D) Tick de exibição e render

1. A cada callback de tempo do `KSPlayerLayer`, o consumidor chama `SubtitleModel.subtitle(currentTime:)` — SwiftUI: `KSVideoPlayer.Coordinator.player(layer:currentTime:totalTime:)` (KSVideoPlayer.swift:271); UIKit: `VideoPlayerView.player(...)` (VideoPlayerView.swift:261-275).
2. `subtitle(currentTime:)` (KSSubtitle.swift:334-358): aplica `currentTime − info.delay − subtitleDelay`, chama `search(for:)` da legenda selecionada; se vier vazio, **mantém** os `parts` atuais que ainda cobrem o tempo (`parts.filter { $0 == currentTime }`, :339-343) — obrigatório porque a fila embutida é consumida na primeira consulta. Se mudou, força `SubtitleModel.textFont` como `.font` em todo `NSMutableAttributedString` (:346-351) e publica `parts`.
3. Render SwiftUI: `VideoSubtitleView` (Sources/KSPlayer/SwiftUI/KSVideoPlayerView.swift:594-617) faz `ZStack { ForEach(model.parts) }`; `SubtitlePart.subtitleView` (:620-664) renderiza `image` posicionada por `UIImage.fitRect` (Sources/KSPlayer/SwiftUI/LiveTextImage.swift:78) ou `Text(AttributedString(text))` com estilo global (`SubtitleModel.textColor/textItalic/textBackgroundColor`) e alinhamento por `textPosition.edgeInsets`; part vazio renderiza `Text("")` para limpar imagem (workaround comentado :659-661).
4. Render UIKit: `VideoPlayerView` usa apenas `parts.first` → `subtitleBackView.image` / `subtitleLabel.attributedText` (VideoPlayerView.swift:264-274).
5. AudioRecognize: `MEPlayerItem.getAudioOutputRender` injeta cada `AudioFrame` no primeiro `AudioRecognize` habilitado (Sources/KSPlayer/MEPlayer/MEPlayerItem.swift:849-857) — na thread de render de áudio.

## Pontos de extensão

- **Novo formato de legenda textual**: implementar `KSParseProtocol` (`canParse(scanner:)` + `parsePart(scanner:)`, KSParseProtocol.swift:14-17) e inserir em `KSOptions.subtitleParses` (:19-21). A ordem importa: o primeiro `canParse == true` vence (KSSubtitle.swift:193). Inserir antes de `SrtParse`, cujo `canParse` é guloso (`contains(" --> ")`).
- **Nova origem de legendas (provider online, NAS, etc.)**: implementar `SubtitleDataSouce` + `SearchSubtitleDataSouce` (busca por título/idioma) ou `FileURLSubtitleDataSouce` (busca pela URL da mídia) (SubtitleDataSouce.swift:63-77) e registrar em `KSOptions.subtitleDataSouces` (:79-81) **antes** de instanciar `SubtitleModel` (a lista é copiada no `init` — campo `subtitleDataSouces`, KSSubtitle.swift:291). Os `infos` devem ser `URLSubtitleInfo` (download+parse já resolvidos) ou qualquer `SubtitleInfo` próprio.
- **Cache customizado de associação mídia→legenda**: implementar `CacheSubtitleDataSouce.addCache(fileURL:downloadURL:)` (SubtitleDataSouce.swift:71-73); o hook de escrita já existe no `selectedSubtitleInfo.didSet` (KSSubtitle.swift:320-322). `PlistCacheSubtitleDataSouce.singleton` é a referência, mas não está registrado por default.
- **Legendas por reconhecimento de fala (paridade Infuse "auto-subs")**: implementar `AudioRecognize` (AudioRecognize.swift:10-12) — receber `AudioFrame` em `append(frame:)`, produzir `SubtitlePart` e respondê-los em `search(for:)`. Registrar em `SubtitleModel.audioRecognizes` (KSSubtitle.swift:290); entram automaticamente em `subtitleInfos` a cada `url.didSet` (:302) e recebem áudio via MEPlayerItem.swift:849-857.
- **Item selecionável arbitrário**: qualquer `SubtitleInfo` pode ser adicionado direto com `SubtitleModel.addSubtitle(info:)` (KSSubtitle.swift:328-332) — deduplicado por `subtitleID`.
- **Estilo global**: estáticos de `SubtitleModel` (`textColor`, `textBackgroundColor`, `textFontSize`, `textBold`, `textItalic`, `textPosition`, KSSubtitle.swift:280-289). São lidos no tick (:349) e no render SwiftUI (:642-646). Para estilo por-parte, o caminho é `SubtitlePart.textPosition` + atributos do `NSAttributedString` gerados no parser.
- **Suporte a tags ASS adicionais**: `String.parseStyle` (KSParseProtocol.swift:175-247) é o switch de tags inline; `parseASSStyle()` (:249-330) o de estilos de cabeçalho (há blocos comentados para `ScaleX/ScaleY/Spacing/SecondaryColour` — pontos óbvios de evolução para paridade com libass/Infuse).
- **Novo codec de legenda embutida**: nada a fazer no Swift — `SubtitleDecode` cobre qualquer codec que o FFmpeg decodifique para `AVSubtitle`; para tratamento especial de bitmap, o gancho é `SubtitleDecode.text(subtitle:)` (SubtitleDecode.swift:89-135).

## Pegadinhas

- **`CircularBuffer.search` é destrutivo** (CircularBuffer.swift:117-137): a consulta de legendas embutidas remove os frames da fila. O fallback `parts.filter` em `SubtitleModel.subtitle(currentTime:)` (KSSubtitle.swift:339-343) é o que mantém a legenda na tela — remover esse fallback quebra silenciosamente as legendas embutidas. Também significa que dois consumidores da mesma track competem pelos frames.
- **Parsers globais stateful**: as instâncias em `KSOptions.subtitleParses` são compartilhadas e `AssParse` acumula `styleMap`/`eventKeys`/`playResX/Y` entre arquivos (KSParseProtocol.swift:40-43) — estilos de um ASS anterior vazam para o próximo parse no mesmo processo. `SubtitleDecode` evita isso com instância própria (`assParse`, SubtitleDecode.swift:21).
- **Threading**: `SubtitleDecode.decodeFrame` roda na thread de leitura do demuxer (`SyncPlayerItemTrack.putPacket` é síncrono, MEPlayerItemTrack.swift:84-92). `SubtitleModel` muta `@Published` e por isso só pode ser tocado na main (o comentário em KSSubtitle.swift:307 e o `DispatchQueue.main.async` existem por isso). O parse de `URLSubtitleInfo` acontece em `Task` não estruturada sem callback — depois de selecionar, `search` retorna `[]` até o parse terminar.
- **Race no `PlistCacheSubtitleDataSouce`**: o `init` popula `srtInfoCaches` em `DispatchQueue.global().async` (SubtitleDataSouce.swift:96-101) enquanto `searchSubtitle`/`addCache` leem/escrevem o mesmo dicionário sem sincronização; um `addCache` cedo pode ser sobrescrito pela carga do plist.
- **Delay de 1s na descoberta de embutidas**: `addSubtitle(dataSouce:)` das tracks embutidas roda 1s após `readyToPlay` (KSVideoPlayer.swift:226-233; VideoPlayerView.swift:288-295). Menus de legenda montados antes disso não veem as tracks; e legendas adicionadas em stream (ex.: HLS) depois desse instante não são recapturadas.
- **`parseDuration` trata centésimos ASS como milissegundos** (Utility.swift:83-100): o campo final é sempre dividido por 1000; timestamps ASS (`0:12:37.73` = 730ms) viram 73ms. SRT (`,184`) e VTT (3 dígitos) ficam corretos. Erro de até ~0,9s em ASS externo carregado via `KSSubtitle.parse` (o caminho embutido não sofre: timing vem do pacote).
- **`AssParse.canParse` pode entrar em loop infinito** com `[Script Info]` sem linha `Format:` — o `while scanner.scanString("Format:") == nil` (KSParseProtocol.swift:48-56) não tem verificação de `isAtEnd`; no fim da string nenhum ramo avança o scanner.
- **Fonte global sobrescreve fonte ASS**: no tick, `SubtitleModel.textFont` é aplicado sobre o range inteiro de qualquer `NSMutableAttributedString` (KSSubtitle.swift:346-351) — como os parsers produzem `NSMutableAttributedString` (via `String.build`), `\fn/\fs` e `Fontname` do ASS são anulados a cada frame exibido. Só `SubtitlePart` criado com `init(_:_:String)` (imutável) escapa do cast.
- **Cores ASS**: formato `&HAABBGGRR` com alpha invertido (`alpha = 1 − AA/255`, `UIColor(abgr:)`, Utility.swift:126-131). `SecondaryColour`/`\2c` são propositalmente ignorados (KSParseProtocol.swift:225-227, 270-273). `Bold` vira `.expansion` (esticamento horizontal) e `Italic` vira `.obliqueness` — aproximações, não traits reais de fonte (:274-279).
- **OpenSubtitles incompleto**: `token` nunca é preenchido (não há chamada de login; `username`/`password` guardados e não usados, SubtitleDataSouce.swift:267-276) e a query usa a chave com typo `"imbd_id"` (:289) — busca por IMDb ID provavelmente não filtra nada na API v1 (que espera `imdb_id`).
- **`Assrt` ignora `languages`** (assinatura `languages _:`, SubtitleDataSouce.swift:203) e faz N+1 requests (um `/detail` por resultado) sequenciais.
- **`searchSubtitle` concorrente**: cada chamada remove os `infos` antigos e dispara `Task`; duas buscas rápidas em sequência podem duplicar itens em `subtitleInfos` (a remoção usa identidade `===` contra a lista atual do data source, KSSubtitle.swift:363-367).
- **`isEnabled` de track de texto embutida é sempre true no demux** (FFmpegAssetTrack.swift:271-273): o `discard` nunca vira `AVDISCARD_ALL` para legendas de texto, e o `isEnabled` "get" reflete o `discard` do stream — logo `autoSelectEmbedSubtitle` (KSOptions.swift:74) seleciona a primeira track de texto mesmo sem `AV_DISPOSITION_DEFAULT`; para bitmap, só entra habilitada se tiver disposition `FORCED` (FFmpegAssetTrack.swift:117-122).
- **UIKit renderiza só `parts.first`** (VideoPlayerView.swift:265): cues simultâneos (diálogo + placa) aparecem apenas no caminho SwiftUI (`ForEach`).
- **`binarySearch` é código morto** (KSSubtitle.swift:215-231): `KSSubtitle.search` usa varredura linear (:155-167) — O(n) por tick; relevante para ASS de karaokê com dezenas de milhares de eventos.
- **Legendas com `end = .infinity`** (bitmap sem `end_display_time`, SubtitleDecode.swift:66-68) só saem da tela quando o próximo evento (ou o part vazio sintético) chega.
- **Nome de arquivo tem typo canônico**: `SubtitleDataSouce` (sem o "r") em tipos e arquivo — buscar por "DataSouce", não "DataSource".

## Relação com outros subsistemas

- **MEPlayer (demux/decodificação)**: `MEPlayerItem` cria as filas de legenda (MEPlayerItem.swift:339-343), roteia pacotes (:565) e re-decodifica após seek (flush em `SyncPlayerItemTrack.seek`, MEPlayerItemTrack.swift:72-82). `SubtitleDecode` é instanciado por `makeDecode` (MEPlayerItemTrack.swift:301-305). Detalhes do pipeline em `docs/03-engine-meplayer-demux-e-pipeline.md` e `docs/04-decodifica-o.md`.
- **Camada AVPlayer/abstração de player**: `MediaPlayerProtocol.subtitleDataSouce` — `KSMEPlayer` devolve a si mesmo (KSMEPlayer.swift:296), `KSAVPlayer` devolve `nil` (KSAVPlayer.swift:363): legendas embutidas só existem no engine FFmpeg; com AVPlayer restam as origens externas.
- **UI SwiftUI**: `KSVideoPlayer.Coordinator` possui o `SubtitleModel` (KSVideoPlayer.swift:117), alimenta o tick (:271) e reseta seleção em `resetPlayer` (:173). `KSVideoPlayerView` monta `VideoSubtitleView` como overlay (KSVideoPlayerView.swift:67), aceita drop/openURL de arquivos de legenda (:306-308) e expõe busca/delay em `VideoSettingView` (:694-700). Menu de seleção em `KSVideoPlayerViewBuilder.subtitleButton` (KSVideoPlayerViewBuilder.swift:41-58).
- **UI UIKit/AppKit**: `PlayerView.srtControl` (PlayerView.swift:51) é o mesmo `SubtitleModel`; `VideoPlayerView` renderiza em `subtitleLabel`/`subtitleBackView` (VideoPlayerView.swift:264-274) e monta menus (:518-522, :580-607). `IOSVideoPlayerView`/`MacVideoPlayerView` setam `selectedSubtitleInfo` a partir de file pickers (IOSVideoPlayerView.swift:396; MacVideoPlayerView.swift:127).
- **Áudio**: `MEPlayerItem.getAudioOutputRender` (MEPlayerItem.swift:849-857) alimenta `AudioRecognize` com cada `AudioFrame` consumido pelo render de áudio — acoplamento direto do pipeline de áudio com `SubtitleModel.audioRecognizes` (estático global).
- **Render de vídeo**: nenhum acoplamento — legendas são sempre uma camada de UI (SwiftUI/UIKit) por cima do `MetalPlayView`/`AVSampleBufferDisplayLayer`, nunca compostas no frame de vídeo. Bitmap subs reutilizam `VideoSwresample` (Resample.swift:146) e `CGImage.combine` (Utility.swift:695) do subsistema de vídeo para conversão PAL8→ARGB.
- **Core/Utility**: `parseDuration`, `UIColor(assColor:)`, `URL.isSubtitle`, `URL.data/download`, `mergeSortBottomUp` (Utility.swift:83, 108, 380, 401, 414, 806); erros em `PlayerDefines.swift:221-223`.
