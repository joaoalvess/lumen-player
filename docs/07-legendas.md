# 07 — Legendas

Escopo: `Sources/Lumen/Subtitle/` (KSSubtitle.swift, KSParseProtocol.swift, SubtitleDataSouce.swift, AudioRecognize.swift, EmbeddedFontRegistry.swift) + `Sources/Lumen/MEPlayer/SubtitleDecode.swift`. Cobre parsing de texto (SRT/VTT/ASS), decodificação de legendas embutidas via FFmpeg (texto e bitmap: VobSub/DVB/PGS), fontes de legenda online (Shooter/Assrt/OpenSubtitles), registro de fontes tipográficas embutidas no container, reconhecimento de áudio (protocolo) e o modelo de exibição/estilo.

## Responsabilidade

O subsistema resolve três problemas independentes e os unifica sob uma única abstração de consulta por tempo (`KSSubtitleProtocol.search(for:)`, `Sources/Lumen/Subtitle/KSSubtitle.swift`):

1. **Legendas externas (arquivo/URL)**: descoberta (diretório local, cache, APIs online), download lazy e parsing de SRT/VTT/ASS em memória (`KSSubtitle.parts: [SubtitlePart]`).
2. **Legendas embutidas no container**: cada stream de legenda vira um `FFmpegAssetTrack` com fila própria de frames decodificados por `SubtitleDecode` (texto ASS/plain ou bitmap convertido em `UIImage`).
3. **Seleção e exibição**: `SubtitleModel` agrega todas as origens em `subtitleInfos`, mantém a seleção (`selectedSubtitleInfo`), aplica delays e estilo global, e publica `parts` (`@Published`) para a UI (SwiftUI `VideoSubtitleView` ou UIKit `VideoPlayerView`).

O contrato central: dado `currentTime`, a legenda ativa retorna os `SubtitlePart` visíveis naquele instante. Tudo o mais (formato, origem, codec) é detalhe encapsulado atrás de `SubtitleInfo`.

## Fluxo de dados

### A) Registro de origens ao trocar de mídia

1. `KSVideoPlayer.Coordinator.makeView` (SwiftUI) seta `subtitleModel.url` (Sources/Lumen/AVPlayer/KSVideoPlayer.swift); no caminho UIKit é `PlayerView.set(url:)` → `srtControl.url` (Sources/Lumen/Core/PlayerView.swift).
2. `SubtitleModel.url.didSet` (KSSubtitle.swift): limpa `subtitleInfos`, chama `searchSubtitle(query: nil, languages: [])` (zera resultados de busca anteriores), anexa `SubtitleModel.audioRecognizes` e itera `KSOptions.subtitleDataSouces` (default `[DirectorySubtitleDataSouce]`) via `addSubtitle(dataSouce:)` — para `FileURLSubtitleDataSouce`, dispara `Task { @MainActor }` com `searchSubtitle(fileURL:)` e anexa `infos` ao terminar. `parts`/`selectedSubtitleInfo` são zerados em `DispatchQueue.main.async` (comentário na :307: não pode mutar `@Published` durante update de UI).
3. Quando o player chega em `.readyToPlay`, o delegate agenda **+1s depois** `addSubtitle(dataSouce: layer.player.subtitleDataSouce)` (legendas embutidas) e, se `options.autoSelectEmbedSubtitle`, seleciona a primeira com `isEnabled` (Sources/Lumen/AVPlayer/KSVideoPlayer.swift; espelhado em Sources/Lumen/Video/VideoPlayerView.swift). O atraso existe porque legendas embutidas no stream de vídeo podem aparecer depois do `readyToPlay` (comentário).
4. Busca online sob demanda: `SubtitleModel.searchSubtitle(query:languages:)` (KSSubtitle.swift) remove os `infos` antigos de cada `SearchSubtitleDataSouce` e refaz a busca em `Task { @MainActor }`. A UI chama isso em `VideoSettingView` (Sources/Lumen/SwiftUI/KSVideoPlayerView.swift).

### B) Seleção e carga

1. UI seta `selectedSubtitleInfo` (menu SwiftUI: Sources/Lumen/SwiftUI/KSVideoPlayerViewBuilder.swift; UIKit: Sources/Lumen/Video/VideoPlayerView.swift; drag-and-drop de arquivo `.srt`: Sources/Lumen/SwiftUI/KSVideoPlayerView.swift).
2. `didSet` (KSSubtitle.swift): `oldValue.isEnabled = false`, novo `isEnabled = true`; se for `URLSubtitleInfo` remoto e existir um `CacheSubtitleDataSouce` registrado, grava o par (URL da mídia → URL da legenda).
3. `URLSubtitleInfo.isEnabled.didSet` (SubtitleDataSouce.swift): se `parts.isEmpty`, dispara `Task` não estruturada com `parse(url: downloadURL, userAgent:)` → `URL.data(userAgent:)` (Sources/Lumen/Core/Utility.swift) → `KSSubtitle.parse(data:encoding:)` → `KSOptions.subtitleParses.first { $0.canParse }` → `parse(scanner:)` → `parts` ordenados (merge sort estável, Sources/Lumen/Core/Utility.swift). Erros viram `NSError(errorCode:)` `.subtitleUnEncoding/.subtitleUnParse/.subtitleFormatUnSupport` (Sources/Lumen/AVPlayer/PlayerDefines.swift) — engolidos pelo `try?` do caller.
4. Para track embutida (`FFmpegAssetTrack`), `isEnabled = true` seta `discard = AVDISCARD_DEFAULT` no stream (Sources/Lumen/MEPlayer/FFmpegAssetTrack.swift). Nota: para legendas de **texto** embutidas o setter força `AVDISCARD_DEFAULT` sempre — todos os streams de texto continuam sendo demuxados/decodificados mesmo desselecionados (troca instantânea). `MEPlayerItem.select(track:)` só dispara re-seek para legendas bitmap com `options.isSeekImageSubtitle` (Sources/Lumen/MEPlayer/MEPlayerItem.swift; `KSOptions.isSeekImageSubtitle`, Sources/Lumen/AVPlayer/KSOptions.swift).

### C) Pipeline embutido (FFmpeg)

1. `MEPlayerItem.createAssetTracks`: para cada stream de legenda cria `SyncPlayerItemTrack<SubtitleFrame>(frameCapacity: 255)` e pendura em `assetTrack.subtitle` (Sources/Lumen/MEPlayer/MEPlayerItem.swift). A fila é `CircularBuffer(sorted: true, expanding: true)` porque "algumas legendas de imagem chegam fora de ordem" (Sources/Lumen/MEPlayer/MEPlayerItemTrack.swift).
2. Thread de leitura: `readLoop` roteia pacotes de legenda para `assetTrack.subtitle?.putPacket(packet:)` (MEPlayerItem.swift). `SyncPlayerItemTrack.putPacket` decodifica **sincronamente na thread de demux** (`doDecode`, MEPlayerItemTrack.swift); `makeDecode` instancia `SubtitleDecode` para mediaType `.subtitle`.
3. `SubtitleDecode.init` (SubtitleDecode.swift): cria o `AVCodecContext` e alimenta `codecContext.subtitle_header` (cabeçalho ASS gerado pelo FFmpeg com `[V4+ Styles]` e `Format:` de eventos) em `assParse.canParse` — isso pré-carrega `styleMap`/`eventKeys` da instância privada de `AssParse`.
4. `decodeFrame` (SubtitleDecode.swift): `avcodec_decode_subtitle2`; calcula `start = pts + start_display_time/1000 − assetTrack.startTime` e `duration` de `end_display_time` (ou `packet.duration` como fallback; se 0 → `end = .infinity`). Se o `AVSubtitle` não gerar parts, insere um `SubtitlePart(0,nil)` vazio para **limpar** a legenda anterior (comentário: usar um frame vazio evita o bug de end<start quando a decodificação chega fora de ordem). Cada part vira `SubtitleFrame` e cai na `outputRenderQueue` via completion.
5. `SubtitleDecode.text(subtitle:)` (SubtitleDecode.swift) trata os 3 tipos de rect:
 - `rect.text` → `NSAttributedString` plano acumulado;
 - `rect.ass` → `assParse.parsePart(scanner:)` (linha sem `Dialogue:`/Start/End → `start=end=0`, sobrescritos pelo timing do pacote; formato exemplificado em KSParseProtocol.swift);
 - `SUBTITLE_BITMAP` (VobSub `AV_CODEC_ID_DVD_SUBTITLE`, DVB, PGS `AV_CODEC_ID_HDMV_PGS_SUBTITLE`; classificação `isImageSubtitle` em FFmpegAssetTrack.swift) → `VideoSwresample(dstFormat: AV_PIX_FMT_ARGB).transfer(format: AV_PIX_FMT_PAL8, ...)` (Sources/Lumen/MEPlayer/Resample.swift) → `CVPixelBuffer.cgImage` → múltiplos rects combinados por `CGImage.combine` (Sources/Lumen/Core/Utility.swift) → PNG → `UIImage` (comentário justifica PNG: precisa de alpha; HEIC trava a main thread; TIFF fica com fundo verde). `part.origin` guarda a posição do primeiro rect.
6. Consulta: `FFmpegAssetTrack.search(for:)` (EmbedDataSouce.swift) roda `outputRenderQueue.search { $0.part == time }` — o `CircularBuffer.search` é **destrutivo**: remove os itens casados e avança o `headIndex` (CircularBuffer.swift).

### D) Tick de exibição e render

1. A cada callback de tempo do `KSPlayerLayer`, o consumidor chama `SubtitleModel.subtitle(currentTime:)` — SwiftUI: `KSVideoPlayer.Coordinator.player(layer:currentTime:totalTime:)` (KSVideoPlayer.swift); UIKit: `VideoPlayerView.player(...)` (VideoPlayerView.swift).
2. `subtitle(currentTime:)` (KSSubtitle.swift): aplica `currentTime − info.delay − subtitleDelay`, chama `search(for:)` da legenda selecionada; se vier vazio, **mantém** os `parts` atuais que ainda cobrem o tempo (`parts.filter { $0 == currentTime }`) — obrigatório porque a fila embutida é consumida na primeira consulta. Se mudou, força `SubtitleModel.textFont` como `.font` em todo `NSMutableAttributedString` e publica `parts`.
3. Render SwiftUI: `VideoSubtitleView` (Sources/Lumen/SwiftUI/KSVideoPlayerView.swift) faz `ZStack { ForEach(model.parts) }`; `SubtitlePart.subtitleView` renderiza `image` posicionada por `UIImage.fitRect` (Sources/Lumen/SwiftUI/LiveTextImage.swift) ou `Text(AttributedString(text))` com estilo global (`SubtitleModel.textColor/textItalic/textBackgroundColor`) e alinhamento por `textPosition.edgeInsets`; part vazio renderiza `Text("")` para limpar imagem (workaround comentado).
4. Render UIKit: `VideoPlayerView` usa apenas `parts.first` → `subtitleBackView.image` / `subtitleLabel.attributedText` (VideoPlayerView.swift).
5. AudioRecognize: `MEPlayerItem.getAudioOutputRender` injeta cada `AudioFrame` no primeiro `AudioRecognize` habilitado (Sources/Lumen/MEPlayer/MEPlayerItem.swift) — na thread de render de áudio.

### E) Fontes embutidas no container — `EmbeddedFontRegistry`

Arquivos MKV com legendas ASS costumam carregar as fontes tipográficas como **attachments** no próprio container. Sem elas, o `Fontname` do bloco `[V4+ Styles]` não resolve e a legenda cai na fonte de sistema, perdendo o visual pretendido. O `EmbeddedFontRegistry` (Sources/Lumen/Subtitle/EmbeddedFontRegistry.swift) resolve isso via **CoreText/CoreGraphics** — não via libass.

- **Tipo**: `public final class EmbeddedFontRegistry: @unchecked Sendable`, singleton `shared`, protegido por `NSLock`.
- **Extração**: durante o mapeamento de streams em `MEPlayerItem`, os streams com `codec_type == AVMEDIA_TYPE_ATTACHMENT` (que não viram `FFmpegAssetTrack`) são passados a `registerEmbeddedFont(stream:)`. Os bytes da fonte vêm de `codecpar.extradata` — é onde o FFmpeg deposita o payload da attachment. Os metadados `mimetype`/`filename` do stream são validados por `EmbeddedFontRegistry.isFontAttachment(mimeType:filename:)`, que reconhece os MIME types usuais de TrueType/OpenType e, como fallback, as extensões `ttf`/`otf`/`ttc`.
- **Registro**: `register(fontData:owner:)` monta um `CGFont` e o registra no processo com `CTFontManagerRegisterGraphicsFont`. Indexa a fonte por três chaves normalizadas (trim + lowercase): PostScript name, family name e full name — ASS pode referenciar qualquer uma delas.
- **Ciclo de vida**: o `owner` é um `UUID` por item de mídia. `unregister(owner:)`, chamado no fechamento do `MEPlayerItem`, faz refcounting manual por PostScript name: se outro item ainda usa a mesma fonte, a posse do registro é transferida; o `CTFontManagerUnregisterGraphicsFont` só acontece quando não sobra ninguém.
- **Consumo**: em `KSParseProtocol.swift`, tanto o parser de tags inline (`\fn`) quanto o de estilos de cabeçalho (`parseASSStyle`) resolvem o nome com `EmbeddedFontRegistry.shared.fontName(for:)` antes de construir a `UIFont`, com fallback para o nome original e depois para a fonte de sistema.
- **Flag**: `KSOptions.registerEmbeddedFonts` (default `true`) desliga a extração inteira.

## Pontos de extensão

- **Novo formato de legenda textual**: implementar `KSParseProtocol` (`canParse(scanner:)` + `parsePart(scanner:)`, KSParseProtocol.swift) e inserir em `KSOptions.subtitleParses`. A ordem importa: o primeiro `canParse == true` vence (KSSubtitle.swift). Inserir antes de `SrtParse`, cujo `canParse` é guloso (`contains(" --> ")`).
- **Nova origem de legendas (provider online, NAS, etc.)**: implementar `SubtitleDataSouce` + `SearchSubtitleDataSouce` (busca por título/idioma) ou `FileURLSubtitleDataSouce` (busca pela URL da mídia) (SubtitleDataSouce.swift) e registrar em `KSOptions.subtitleDataSouces` **antes** de instanciar `SubtitleModel` (a lista é copiada no `init` — campo `subtitleDataSouces`, KSSubtitle.swift). Os `infos` devem ser `URLSubtitleInfo` (download+parse já resolvidos) ou qualquer `SubtitleInfo` próprio.
- **Cache customizado de associação mídia→legenda**: implementar `CacheSubtitleDataSouce.addCache(fileURL:downloadURL:)` (SubtitleDataSouce.swift); o hook de escrita já existe no `selectedSubtitleInfo.didSet` (KSSubtitle.swift). `PlistCacheSubtitleDataSouce.singleton` é a referência, mas não está registrado por default.
- **Legendas por reconhecimento de fala (paridade Infuse "auto-subs")**: implementar `AudioRecognize` (AudioRecognize.swift) — receber `AudioFrame` em `append(frame:)`, produzir `SubtitlePart` e respondê-los em `search(for:)`. Registrar em `SubtitleModel.audioRecognizes` (KSSubtitle.swift); entram automaticamente em `subtitleInfos` a cada `url.didSet` e recebem áudio via MEPlayerItem.swift.
- **Item selecionável arbitrário**: qualquer `SubtitleInfo` pode ser adicionado direto com `SubtitleModel.addSubtitle(info:)` (KSSubtitle.swift) — deduplicado por `subtitleID`.
- **Estilo global**: estáticos de `SubtitleModel` (`textColor`, `textBackgroundColor`, `textFontSize`, `textBold`, `textItalic`, `textPosition`, KSSubtitle.swift). São lidos no tick e no render SwiftUI. Para estilo por-parte, o caminho é `SubtitlePart.textPosition` + atributos do `NSAttributedString` gerados no parser.
- **Suporte a tags ASS adicionais**: `String.parseStyle` (KSParseProtocol.swift) é o switch de tags inline; `parseASSStyle` o de estilos de cabeçalho (há blocos comentados para `ScaleX/ScaleY/Spacing/SecondaryColour` — pontos óbvios de evolução para paridade com libass/Infuse).
- **Novo codec de legenda embutida**: nada a fazer no Swift — `SubtitleDecode` cobre qualquer codec que o FFmpeg decodifique para `AVSubtitle`; para tratamento especial de bitmap, o gancho é `SubtitleDecode.text(subtitle:)` (SubtitleDecode.swift).

## Pegadinhas

- **`CircularBuffer.search` é destrutivo** (CircularBuffer.swift): a consulta de legendas embutidas remove os frames da fila. O fallback `parts.filter` em `SubtitleModel.subtitle(currentTime:)` (KSSubtitle.swift) é o que mantém a legenda na tela — remover esse fallback quebra silenciosamente as legendas embutidas. Também significa que dois consumidores da mesma track competem pelos frames.
- **Parsers globais stateful**: as instâncias em `KSOptions.subtitleParses` são compartilhadas e `AssParse` acumula `styleMap`/`eventKeys`/`playResX/Y` entre arquivos (KSParseProtocol.swift) — estilos de um ASS anterior vazam para o próximo parse no mesmo processo. `SubtitleDecode` evita isso com instância própria (`assParse`, SubtitleDecode.swift).
- **Threading**: `SubtitleDecode.decodeFrame` roda na thread de leitura do demuxer (`SyncPlayerItemTrack.putPacket` é síncrono, MEPlayerItemTrack.swift). `SubtitleModel` muta `@Published` e por isso só pode ser tocado na main (o comentário em KSSubtitle.swift e o `DispatchQueue.main.async` existem por isso). O parse de `URLSubtitleInfo` acontece em `Task` não estruturada sem callback — depois de selecionar, `search` retorna `[]` até o parse terminar.
- **Race no `PlistCacheSubtitleDataSouce`**: o `init` popula `srtInfoCaches` em `DispatchQueue.global.async` (SubtitleDataSouce.swift) enquanto `searchSubtitle`/`addCache` leem/escrevem o mesmo dicionário sem sincronização; um `addCache` cedo pode ser sobrescrito pela carga do plist.
- **Delay de 1s na descoberta de embutidas**: `addSubtitle(dataSouce:)` das tracks embutidas roda 1s após `readyToPlay` (KSVideoPlayer.swift; VideoPlayerView.swift). Menus de legenda montados antes disso não veem as tracks; e legendas adicionadas em stream (ex.: HLS) depois desse instante não são recapturadas.
- **`parseDuration` trata centésimos ASS como milissegundos** (Utility.swift): o campo final é sempre dividido por 1000; timestamps ASS (`0:12:37.73` = 730ms) viram 73ms. SRT (`,184`) e VTT (3 dígitos) ficam corretos. Erro de até ~0,9s em ASS externo carregado via `KSSubtitle.parse` (o caminho embutido não sofre: timing vem do pacote).
- **`AssParse.canParse` pode entrar em loop infinito** com `[Script Info]` sem linha `Format:` — o `while scanner.scanString("Format:") == nil` (KSParseProtocol.swift) não tem verificação de `isAtEnd`; no fim da string nenhum ramo avança o scanner.
- **Fonte global sobrescreve fonte ASS**: no tick, `SubtitleModel.textFont` é aplicado sobre o range inteiro de qualquer `NSMutableAttributedString` (KSSubtitle.swift) — como os parsers produzem `NSMutableAttributedString` (via `String.build`), `\fn/\fs` e `Fontname` do ASS são anulados a cada frame exibido. Só `SubtitlePart` criado com `init(_:_:String)` (imutável) escapa do cast. **Isso vale também para as fontes embutidas**: o `EmbeddedFontRegistry` resolve corretamente o nome no parse, mas o tick sobrescreve o atributo `.font` logo depois — para ver a fonte do container na tela é preciso não forçar `textFont` global.
- **Cores ASS**: formato `&HAABBGGRR` com alpha invertido (`alpha = 1 − AA/255`, `UIColor(abgr:)`, Utility.swift). `SecondaryColour`/`\2c` são propositalmente ignorados (KSParseProtocol.swift). `Bold` vira `.expansion` (esticamento horizontal) e `Italic` vira `.obliqueness` — aproximações, não traits reais de fonte.
- **OpenSubtitles incompleto**: `token` nunca é preenchido (não há chamada de login; `username`/`password` guardados e não usados, SubtitleDataSouce.swift) e a query usa a chave com typo `"imbd_id"` — busca por IMDb ID provavelmente não filtra nada na API v1 (que espera `imdb_id`).
- **`Assrt` ignora `languages`** (assinatura `languages _:`, SubtitleDataSouce.swift) e faz N+1 requests (um `/detail` por resultado) sequenciais.
- **`searchSubtitle` concorrente**: cada chamada remove os `infos` antigos e dispara `Task`; duas buscas rápidas em sequência podem duplicar itens em `subtitleInfos` (a remoção usa identidade `===` contra a lista atual do data source, KSSubtitle.swift).
- **`isEnabled` de track de texto embutida é sempre true no demux** (FFmpegAssetTrack.swift): o `discard` nunca vira `AVDISCARD_ALL` para legendas de texto, e o `isEnabled` "get" reflete o `discard` do stream — logo `autoSelectEmbedSubtitle` (KSOptions.swift) seleciona a primeira track de texto mesmo sem `AV_DISPOSITION_DEFAULT`; para bitmap, só entra habilitada se tiver disposition `FORCED` (FFmpegAssetTrack.swift).
- **UIKit renderiza só `parts.first`** (VideoPlayerView.swift): cues simultâneos (diálogo + placa) aparecem apenas no caminho SwiftUI (`ForEach`).
- **`binarySearch` é código morto** (KSSubtitle.swift): `KSSubtitle.search` usa varredura linear — O(n) por tick; relevante para ASS de karaokê com dezenas de milhares de eventos.
- **Legendas com `end = .infinity`** (bitmap sem `end_display_time`, SubtitleDecode.swift) só saem da tela quando o próximo evento (ou o part vazio sintético) chega.
- **Nome de arquivo tem typo canônico**: `SubtitleDataSouce` (sem o "r") em tipos e arquivo — buscar por "DataSouce", não "DataSource".

## Relação com outros subsistemas

- **MEPlayer (demux/decodificação)**: `MEPlayerItem` cria as filas de legenda (MEPlayerItem.swift), roteia pacotes e re-decodifica após seek (flush em `SyncPlayerItemTrack.seek`, MEPlayerItemTrack.swift). `SubtitleDecode` é instanciado por `makeDecode` (MEPlayerItemTrack.swift). Detalhes do pipeline em `docs/03-engine-meplayer-demux-e-pipeline.md` e `docs/04-decodifica-o.md`.
- **Camada AVPlayer/abstração de player**: `MediaPlayerProtocol.subtitleDataSouce` — `KSMEPlayer` devolve a si mesmo (KSMEPlayer.swift), `KSAVPlayer` devolve `nil` (KSAVPlayer.swift): legendas embutidas só existem no engine FFmpeg; com AVPlayer restam as origens externas.
- **UI SwiftUI**: `KSVideoPlayer.Coordinator` possui o `SubtitleModel` (KSVideoPlayer.swift), alimenta o tick e reseta seleção em `resetPlayer`. `KSVideoPlayerView` monta `VideoSubtitleView` como overlay (KSVideoPlayerView.swift), aceita drop/openURL de arquivos de legenda e expõe busca/delay em `VideoSettingView`. Menu de seleção em `KSVideoPlayerViewBuilder.subtitleButton` (KSVideoPlayerViewBuilder.swift).
- **UI UIKit/AppKit**: `PlayerView.srtControl` (PlayerView.swift) é o mesmo `SubtitleModel`; `VideoPlayerView` renderiza em `subtitleLabel`/`subtitleBackView` (VideoPlayerView.swift) e monta menus. `IOSVideoPlayerView`/`MacVideoPlayerView` setam `selectedSubtitleInfo` a partir de file pickers (IOSVideoPlayerView.swift; MacVideoPlayerView.swift).
- **Áudio**: `MEPlayerItem.getAudioOutputRender` (MEPlayerItem.swift) alimenta `AudioRecognize` com cada `AudioFrame` consumido pelo render de áudio — acoplamento direto do pipeline de áudio com `SubtitleModel.audioRecognizes` (estático global).
- **Render de vídeo**: nenhum acoplamento — legendas são sempre uma camada de UI (SwiftUI/UIKit) por cima do `MetalPlayView`/`AVSampleBufferDisplayLayer`, nunca compostas no frame de vídeo. Bitmap subs reutilizam `VideoSwresample` (Resample.swift) e `CGImage.combine` (Utility.swift) do subsistema de vídeo para conversão PAL8→ARGB.
- **Core/Utility**: `parseDuration`, `UIColor(assColor:)`, `URL.isSubtitle`, `URL.data/download`, `mergeSortBottomUp` (Utility.swift); erros em `PlayerDefines.swift`.
